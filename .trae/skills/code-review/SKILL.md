# 代码审查

## 审查范围

### 1. 空指针检查
- 检查未初始化的变量和对象引用
- 检查可能为 null/undefined 的值的使用
- 验证函数参数的空值检查
- 检查数组访问是否越界

### 2. 内存泄漏检查
- 检查未释放的资源（文件、数据库连接、网络连接等）
- 检查循环引用导致的内存泄漏
- 检查定时器和事件监听器的正确清理
- 检查大型对象的合理使用

### 3. 接口幂等性检查
- 验证 RESTful API 的幂等性设计
- 检查重复请求的处理机制
- 验证事务的原子性和一致性
- 检查缓存策略是否合理

### 4. 日志规范检查
- 检查日志级别使用是否适当
- 验证日志内容是否包含敏感信息
- 检查日志格式是否统一
- 验证异常处理中的日志记录

## 触发条件

当用户使用以下触发词时，调用此技能：
- 代码审查
- 帮我看代码

## 使用方法

1. 用户请求代码审查并提供代码或文件路径
2. 分析代码中的潜在问题
3. 提供详细的审查报告和改进建议
4. 验证修复后的代码是否符合规范

```

   - 问题：具体描述

2. **内存泄漏问题**
   - 位置：文件路径:行号
   - 问题：具体描述
   - 建议：修复方案

3. **接口幂等性问题**
   - 位置：文件路径:行号
   - 问题：具体描述
   - 建议：修复方案

4. **日志规范问题**
```
